Design Guide v0.1 Windows 11 Desktop · Offline only

Meeting Recorder & Speaker Marker
Design specification for the build agent

One Windows 11 machine sits in the room, records the whole meeting to a single audio file, and lets one operator mark who is speaking by clicking a name or pressing a number key. The output is an MP3 plus a Markdown file of speaker names and timestamp ranges. Those two files are then handed to an LLM to produce a per-speaker transcript. Nothing else belongs in this product.

Read this document top to bottom before writing code. Sections 01–03 are constraints, 04–08 are the screens, 09 is the keyboard model, and 10–11 are contracts to implement exactly.

Resolved conflict

The written brief described an Android phone app; the platform answer was Windows 11 desktop only. Desktop wins. Every phone-specific assumption has been dropped: the layout is now a single resizable window, marking is keyboard-first, and the microphone is the PC's own input rather than a handset.

Assumed, needs confirming

Audio comes from the PC's own microphone, one input device, recording the room. System-audio capture (the far end of the Teams/Meet call) is not in this version; the room mic picks up the room speakers. With ten people around a table this is the weakest link in the chain — the setup screen therefore makes the level check unskippable.

Offline only

No network calls, no accounts, no telemetry, no cloud sync. Everything lives in a local folder the user picks. The app must work with the network adapter disabled, and must never show a spinner that waits on a server.

First principle

The operator is also a participant. They will look away, mis-click, and forget to close a mark. Recording never stops for any reason, and every mistake is repairable in under three seconds without leaving the recording screen.

01

What we took from Ultraschall

Coloured markers as the primary object

Ultraschall's editing model is a timeline covered in coloured markers you place live and clean up later. We copy that literally: a mark is a coloured block with a start and an end, owned by one speaker, and it is the only data the app produces besides audio.

Chapter marker lines over the waveform

Ultraschall draws a thin vertical line with a flag where a chapter starts. We reuse the shape for speaker changes: a 1px line at every mark boundary with the speaker's initial in a small flag, drawn on top of the waveform so the operator can read turn-taking at a glance.

Grid rules
· Column count and tile height are derived from speaker count alone. The user cannot set them.
· Tile order is roster order, fixed for the whole session. Never sort by talk time — a moving target defeats muscle memory.
· Widening the window widens tiles; it does not add columns. Height above the minimum goes to the marks dock.
· Minimum window: 1180 × 760. Below that the app refuses to shrink further.
· Above 12 speakers, the grid scrolls and the header warns: mark absent participants instead.

Dock rules

The recording UI never disappears. Expanding the dock takes space from the speaker grid's spare height and from the live waveform (132px → 72px), never from the timecode, the speaker tiles or the Stop button.
No modals, ever. Reassign is an inline dropdown; delete is immediate with a 6-second undo toast. A confirmation dialog in the middle of a meeting is a dialog nobody reads.
0.5 s nudge step, 0.1 s on key-repeat. Start can never pass end. If an edit overlaps a neighbour, the neighbour is trimmed and a toast says which one.
The app flags its own suspects. Marks under 2 seconds, and gaps under 0.3 s between two marks of different speakers, get a red hairline and a one-line hint. This is the single most valuable feature for transcript quality.
Keys live on the preset. Each roster row carries its own hotkey cell, and a preset stores names, roles, slot colours and key assignments together. Two speakers can never hold the same key — the cell rejects an already-taken combination at keystroke time rather than accepting it and warning later. A speaker added mid-session with Ctrl+N takes the lowest free key automatically, so marking continues without a dialog.
Editing is journalled. Every edit appends to an on-disk operation log, so a crash mid-meeting loses at most the last operation, never the session.

Not a separate window and not persistent — this is the confirmation toast. When the app is in the background and a global hotkey fires, this toast appears at the bottom-right of the primary display for 2 seconds and fades. Stop is the only exit, and it is guarded

Pressing Stop shows one inline confirmation strip at the top of S3 — “Stop recording? 47:32 captured · Enter to confirm, Esc to keep going” — not a modal. The window close button is disabled while recording; closing the window minimises to the mini bar instead.
Any mark still open at Stop is closed at the stop timestamp and flagged in the Markdown with auto-closed. Pause closes the open mark the same way and drops the paused span out of the file entirely — the timeline the operator sees after resuming is continuous, because the file is.
Audio is encoded to MP3 during the meeting in append mode, and the mark journal is flushed on every change. If the machine dies, S1 offers a one-click recovery that rebuilds the Markdown from the journal.
09

Keyboard map

1 … 9, 0Toggle mark for speaker 1–10. 0 is speaker 10.
Shift+1, Shift+2Speakers 11 and 12. Shift is only a prefix for these two — Shift+3…0 are unbound, not aliases.
SpaceClose the open mark without opening another (silence / crosstalk).
Ctrl+Z / Ctrl+YUndo / redo the last mark operation. Unlimited depth within a session.
Ctrl+PPause / resume. The audio is cut and rejoined, so paused time does not exist in the file.
Ctrl+EExpand / collapse the marks dock.
↑ ↓Move the dock selection. Enter opens a row for editing.
← → / Shift+←→Nudge the selected boundary 0.5 s / 0.1 s.
Ctrl+NAdd a speaker mid-session; the roster grows and hotkeys renumber only by appending.
EscStop (asks once). Never quits the app.
Alt+1…0Global hotkeys — work while Teams or any other app has focus. Alt+Shift+1/2 for slots 11–12. Each press raises a 2-second toast and nothing else; focus is never taken.
Marking semantics — tap toggle with auto-continue
· Press A → A's mark opens at now − 0.8 s.
· Press B while A is open → A closes at now, B opens at now. One boundary, no gap. This is the common case and must feel instant.
· Press A again while A is open → A closes. Nothing opens.
· Press A within 1.2 s of A closing → the app reopens the previous mark rather than creating a short second one. This silently repairs the most common double-tap error.
· Overlap off (default): opening B always closes A. Overlap on: both stay open and the block lane splits into two rows.
· A key press is always accepted, even mid-encode. Input handling must not sit on the audio thread.

Why both a table and a gaps section. An LLM given only speaker rows will silently invent attribution for the space between them. Listing gaps explicitly is what keeps the transcript honest.

11

Build notes

Stack

WinUI 3 / Windows App SDK, C#, packaged MSIX. Mica off — this app owns a flat dark ground, and Mica would let the desktop wallpaper through a screen the operator stares at for an hour.
Fluent's motion and focus behaviour is kept; Fluent's colours are replaced wholesale by the tokens in section 02.
Capture with WASAPI (AudioGraph or NAudio). Encode with a bundled LAME; no ffmpeg process, no download at runtime.
If WinUI 3 is not viable for you, ask before switching to WPF — the layout survives either, the dependency story does not.

Non-negotiable behaviour

Audio capture and encoding run on a dedicated thread; nothing in the UI can block them. Dropped-frame count is surfaced in the header, not swallowed.
Mark state is appended to marks.jsonl and fsync'd on every operation.
Sleep and display-off are inhibited for the session duration. The screen dims but does not lock.
Device unplugged mid-session → keep recording from the fallback device, write a note into the Markdown, show a persistent banner. Never stop.
Timestamps come from the audio sample count, not the wall clock, so drift cannot desynchronise the marks from the file.
Pause cuts the audio and rejoins it, so the file is shorter than the meeting. Every timestamp is measured against the file, not the clock — an LLM seeking to 00:31:14 in the MP3 lands exactly on the marked speech. Wall-clock times are kept in session.json only.
Marking is a single-operator job and the operator is an ordinary speaker with an ordinary slot and key — no privileged row, no separate colour.

Explicitly out of scope

Automatic speaker diarisation or on-device speech recognition. A human is the classifier here; that is the whole premise.
Joining the Teams/Meet call, bots, calendar integration, cloud storage, sharing links, multi-user editing.
Editing the audio itself. The MP3 is never cut, only marked.
Themes. There is one dark theme.

Open with you, not with the agent

1 · Windows or Android? This is built for Windows per your answer, but the original brief was a phone. If both are real, the phone version needs its own layout pass — the desktop grid does not fold down.
2 · System-audio capture. Assumed out. If remote participants are quiet through the room speakers, adding a second capture lane changes the setup screen and the audio pipeline.
3 · Markdown shape. You left the format to me. Section 10 is a proposal — if the consuming prompt on the Gemini/Claude side expects something else, that wins.
4 · User-assigned hotkeys. Defaults are Alt+1…0 and Alt+Shift+1/2, and the user can reassign any of them. The app must test each registration at start and mark the ones Windows refused, since a silently unregistered hotkey looks identical to a missed press. Where the remapping UI lives is the open question.
5 · Who else uses this? Presets, roster and folder layout assume one operator on one machine. Shared use would change S1 substantially.
